# Pain Log — 构建一个「真的能用」的 learning agent 的真实踩坑史

> 按时间线整理自真实开发聊天记录（2026-07-05 → 2026-08-08）与 git 历史。
> 每条：**症状 → 根因 → 修法 → 可迁移教训**。
> 这份文档的价值主张：下一个教育 agent 项目可以直接对照——大概率会在同样的地方摔倒。

---

## 阶段一：从 Demo 到原型（2026-07-05 ~ 07-07）

### P1. 「Demo 很好看，但没有教学意义」

- **症状**：第一批 3D 演示（太阳系等）视觉不错，但用户第一反应是 *"these demos look great, however, not pedagogically make sense"*——没有可观察的参数、不能操作、看完学不到东西。
- **修法**：给场景加可拖动的 3D 数据面板、学生可操作的实验步骤（O₂ 制备状态机：检查→装药→加热→收集→验满）。
- **教训**：**「能看」和「能学」之间隔着可操作性与可观察性**。这是后来 aha keys / buildIdea（predict→act→observe→articulate）的种子。

### P2. 故意留错，验证「打字改课」

- 做 O₂ 实验时故意保留一个科学错误（收集瓶不取出翻转就复燃火柴），让老师用聊天修正——验证了产品核心主张「老师打字就能改项目」。
- **教训**：给关键能力设计一个**可演示的最小验证场景**，比空谈功能有说服力。

### P3. 「Cursor 差距」——项目最重要的一次觉醒

- **症状**（07-06）：*"当我用 Cursor 里的 fable5 搭 demo 时，可以生成很高质量的场景……我们目前的产品做不到"*。同模型，产品内产出显著差于 Cursor 徒手写码。
- **根因**：产品只给了 `add_asset` 等粗粒度工具，模型**没有写代码发明新物体的通道**。
- **修法**：AI 代码沙盒（`create_custom_object` / `set_behavior` + 工具箱 T + `new Function` 隔离）+ 质量标准写进 system prompt + 工具循环上限 14→20。
- **教训**：**agent 产出质量的天花板 = 你给它的行动通道的表达力**。别急着怪模型。

### P4. Fable「Planner 未返回 JSON」/ 只回 “Done.”

- **症状**：切到 Fable 5 报错，其他模型正常；有时执行阶段无工具卡直接 “Done.”。
- **根因**：这代模型 adaptive thinking 永远开启且 **thinking tokens 计入 max_tokens**；预算小 → thinking 吃光 → 静默截断。且当时 `parseSSE` 丢掉了 `usage`，截断完全不可见。
- **修法**：捕获 usage/stop_reason + 结构化日志（`logs/*.jsonl`）；planner effort low + 大预算；`max_tokens` 截断自动×2 重试；不给这代模型发 `thinking:{type:...}`（会 400）。
- **教训**：**先建可观测性，再谈调优**。「模型时好时坏」几乎都是预算/截断/上下文问题。

### P5. 五分钟的黑盒等待

- **症状**：平均一个项目思考约 5 分钟，用户只看到 "…"。
- **修法**：流式输出 + thinking 摘要实时展示（可折叠）+ 简单任务自动降 effort。
- **教训**：**感知速度 ≈ 真实速度 × 透明度**。看得见推理的 5 分钟可接受，黑盒 1 分钟都嫌久。

### P6. 巨石对象（monolith）

- **症状**：模型把整个生态系统塞进一个 `create_custom_object`；用户说「管道歪了」→ 只能删掉重建整个对象。
- **修法**：粒度硬规则（一对象一逻辑实体）写进 skill + 工具文档；跨对象状态用 controller 模式。
- **教训**：**可修改性是生成质量的一部分**——不能局部修改的高质量产物，等于低质量。

### P7. 杂项：撤销后相机冻结、say() 刷屏、面板文字改不掉

- 撤销后视角锁死（状态恢复没解开 controls）；条件 `T.say` 每帧触发刷屏（→ 锁存规则 + 5s 同文去重兜底）；面板直接编辑改不动（WebGL2 纹理存储尺寸不可变 → 行数变化必须 dispose 旧纹理重建）。
- **教训**：**浏览器/WebGL 的资源生命周期陷阱要写进文档**，每个新会话都可能重踩。

## 阶段二：平台化打磨（2026-07-08 ~ 07-12）

### P8. 「不要 Play/Edit 双模式」被现实推翻

- 最初为降低老师认知负担刻意不做 Unity 式双模式；真实使用发现交互对象「一点就触发，没法选中改 Transform」。07-08 引入显式 play/edit（▶ 复用），edit 全静态、play 跑交互，Alt+click 兜底选中。
- **教训**：**简化设计要接受现实检验**，被推翻时干脆利落地翻案并记录原因。

### P9. Play 模式改了的东西停不掉 / Agent 边玩边改被回滚

- 引入 play-reset 深快照（进 play 快照全场景，停止时还原）；边玩边让 Agent 改场景 → turn 结束刷新回滚基线，防止「停止播放洗掉 AI 工作」。
- **教训**：**「运行态可变 + 可回滚」需要显式快照系统**，浏览器场景和游戏引擎一样逃不掉。

### P10. 多楼层走不上去、面板穿墙、房间没门

- 碰撞最初是 2D 身体带过滤（y 恒 0）→ 二楼永远不可达 → 升级 height-aware（可踏台阶 ≤ 脚高+0.45）；面板穿墙被裁 → 「人在房外隐藏房内面板，人在房内面板顶层渲染」的平台规则；模型建房偶尔忘门 → builder 强制 fallback 到南墙开门。
- **教训**：**空间正确性（门、台阶、栏杆、遮挡）必须由确定性 builder 保证**，这类错误 prompt 是治不住的。

## 阶段三：从场景工具到课程平台（2026-08-04 ~ 08-05）

### P11. Docling 接入与环境地狱

- PDF/Word → md+图的解析服务接入时：`requirements.txt` GPU/CPU 版本、RapidOCR 模型下载、启动语法错误等一连串环境问题。
- **教训**：重依赖的解析服务要**独立成服务 + 明确的安装脚本**，别让它污染主应用的零构建特性。

### P12. 「界面语言 ≠ 材料语言」

- 上传英文 PDF，摘要/大纲却输出中文（或反之）。修法：所有生成物语言跟随**网站 UI 语言**，不跟材料语言。
- **教训**：多语言产品要早定「语言跟随谁」的唯一规则，写进每个生成 prompt。

### P13. 大纲质量差 → 用户亲自提出 KG-first 管线

- **症状**：任意 PDF 直接变大纲：漏内容、无最低配置（没有 reading/quiz）、3D 面板文字溢出重叠。
- **转折**（08-05）：用户直接描述了理想管线：*"1, parse PDF -> md + img (每张图先打标) 2, ... 先建 KG/mindmap 再走大纲"*，并要求 **"PLZ just do it, do this instead of keeping the old pipeline"**——果断替换而非兼容旧管线。
- **修法**：`course_tag_figures → extractKgAndOutlinePlan（STEP-0 aha → KG → 大纲）→ 分节 fan-out 填充`；强制 ≥1 reading + ≥1 quiz；3D 面板文字宽度约束写进 prompt。
- **教训**：**管线级重构不要做兼容层**——两条管线并存的维护成本远高于一次干净替换。

### P14. Learn mode 细节风暴

- 学习模式该看到 LEARNER VIEW（不是编辑器视角）；未完成的课程要灰掉 Start Learning（→ 每节 buildStatus + 绿点体系）；H5 固定盒子内滚动难受（→ iframe 高度自适应）；quiz 交互样式（大按钮 vs 小 toggle）……以及 **📘 Learning companion**（学习模式里的学生侧 agent）接不上模型的报错修复。
- **教训**：**创作端和学习端是两个产品**，学习端的每个细节（视角、门禁、反馈)都要单独走查。

### P15. 滚轮让所有 3D 场景黑屏

- **症状**：任意 3D 场景滚动鼠标滚轮 → 全部 3D 场景黑屏。相机缩放代码在某处产生 NaN/Infinity 并写进共享相机状态。
- **教训**：**共享单例（相机/渲染器）被坏值污染会跨场景传播**——数值输入处夹紧（sanitize），恢复路径上校验相机状态。

### P16. localStorage 配额爆炸

- **症状**：保存弹 `QuotaExceededError`。根因：每节 3D 快照带全量几何/材质/canvas 纹理 dataURL，一门课轻松超 5MB。
- **修法**：slimSnapshot（builderCode 桩 + panelSpec 镜像替代纹理）+ 写入失败驱逐最老项目。
- **教训**：**浏览器持久层要按「配额预算」设计序列化格式**，能重建的一律不入库。

## 阶段四：3D 多节隔离大战（2026-08-05 ~ 08-06）

> 这一阶段集中爆发了「一门课多个 3D 节」的全部并发/状态问题，是整个项目最难的一段。

### P17. 只有第一个 3D 节有内容，其余全空

- **根因**：多节填充时 live 场景绑定竞态——第二节开始填充时，viewer 还 pin 在第一节；空场景被当作快照存进了后续节。
- **修法**：填充期间硬 pin（`fillingVrSectionId`）+ 空快照拒存 + 完成时直接从 live 场景抓取。

### P18. 两个 3D 场景一模一样（A A B / B A A）

- **根因**：各节独立生成互不知情，同一份材料喂出同样的场景；显示名不同但内容相同，名字比对查不出来。
- **修法**：内容签名（builderCode 结构 + 面板文本）+ prompt 注入 peer 场景清单 + 撞签名带 CRITICAL REBUILD 指令重试 + fallback 场景本身多样化。

### P19. Opus 生成的 3D 在大纲上全空（Sonnet 正常）

- **根因链**：早期设了「skills/tools 主要给低档模型，高档模型多自由」的规则 → Opus 走了更自由的路径，生成了**不可序列化的几何写法** → `ObjectLoader.parse` 整体失败 → 空场景。
- **修法**：逐对象恢复 + builderCode 重建兜底 + prompt 加 SNAPSHOT-SAFE GEOMETRY 硬规则（对所有模型生效）。
- **教训**：**「给强模型更多自由」的自由必须止步于数据契约**——序列化安全这类硬约束对任何档位的模型都是铁律。

### P20. 在聊天里改一节，别的节遭殃

- **症状**：让 agent 改某节内容 → 大纲凭空多出空节、已生成的 3D 变空、绿点消失存不了档。
- **根因**：agent 有权限做未经请求的结构操作；新节自动激活把 live 场景换掉；工具循环后没有把 live 编辑持久化。
- **修法**：结构工具加 `requested_by_teacher` 门禁 + 拒绝添加空白节；新节不自动激活；每次工具调用后持久化 live 场景（persistLiveVrEdit）；`course-live-edit` skill 明确「就地编辑、未经请求不得动结构」。
- **教训**：**agent 的权限要按「用户请求范围」收敛**，尤其是结构性写操作。

### P21. 白面板（A→B→A 面板变白方块）

- **根因**：快照瘦身正确地剥掉了面板纹理，指望加载时从 `panelSpec` 重建；但旧存档里序列化出的「僵尸 panelData」（`{canvas:{},tex:{uuid}}`，truthy 但不可用）让重建函数**误以为面板还活着**而提前返回 → 无贴图 → 白板。
- **修法**：`isUsablePanelData` 严格校验（canvas 是真 HTMLCanvas、tex 是真 Texture）；僵尸一律删除后从 spec 全量重建；捕获阶段就删僵尸防再入库；旧样例文件批量清洗。
- **教训**：**「truthy ≠ 可用」**。跨序列化边界的对象要用结构校验而不是存在性检查。

## 阶段五：部署与内容运营（2026-08-06 ~ 08-08）

### P22. GitHub Pages 上图全挂 / 修好又挂

- **第一轮**：课程包里图用 data URI（包 2MB+）或 `/uploads/` 绝对路径（Pages 子路径下 404）→ 改成外置资产 + `sample-asset:` 令牌，打开时按当前部署 origin 解析。
- **第二轮**（「修好又挂」）：其实是**部署失败**——最新 commit 的 Pages deploy 挂了，线上还是旧版本；且 `fetch(..., {cache:'force-cache'})` 把浏览器**永远钉死在第一次缓存的包**上。后来还叠加了 GitHub Actions/Pages 全球大故障（误按 Unpublish 更是雪上加霜）。
- **修法**：令牌解析下沉到**所有课程加载路径**（含存档/草稿/导入，顺带跨 origin 重定位）；`force-cache` → `no-cache`（ETag 304 依然省流量）；诊断时直接 curl 线上文件 + GitHub API 查部署状态。
- **教训**：①「又坏了」先确认**线上跑的到底是哪个版本**（diff 线上文件 vs 本地）；② fetch 缓存策略是隐形状态，`force-cache` 慎用；③ 便携性令牌（相对引用方案）要在**统一的加载入口**解析，不能只在一条路径上。

### P23. 图文错配（图的标签骗人）

- **症状**：「VSEPR 分子几何图」显示的是 PDF 制作机构的 logo；CO₂ 章节配了 ClF₄ 的图；物理课多个 chunk 配了不相关的轮胎摩擦图。
- **根因**：图提取时按**邻近文本**打的 alt 标签不可靠；提取器漏掉了真正相关的图（CO₂ 全套步骤图没提出来）。
- **修法**：逐张**视觉查看**所有已提取图 + 重新提取 PDF 里被漏掉的图 + 按 chunk 文本重新分配 + 真没有的用 gpt-image 生成；修改脚本严格 diff 校验「只动被点名的 chunk」。
- **教训**：**内容质检必须眼见为实**；批量修改要带「只改目标、其余 byte 级不变」的验证。

### P24. 研究工具的分寸感

- 做 usability study 材料时，第一版给了 PhD 级的全套（知情同意、randomization protocol…），用户纠正：*"this is not a phd lv research, just a course project"* → 最终只要一页 RA run sheet。
- **教训**：**交付物的严谨度要匹配场景**，过度工程化的文档和过度工程化的代码一样是浪费。

## 元教训（Meta）

1. **可观测性永远先行**——日志/usage/stop_reason 没有之前，一切调优都是玄学。
2. **数据契约 > 模型自觉**——aha schema、KG 校验、序列化安全、所有权印章，都是把「希望模型做对」变成「程序保证做对」。
3. **每一层共享可变状态（live 场景、相机单例、localStorage、浏览器缓存）都会产生一类专属 bug**——为它们各配快照/校验/守卫。
4. **用户的直觉常常是对的管线设计**（KG-first 是用户提出的），工程师的价值是把直觉变成可校验的契约。
5. **修 bug 之后要能证明「只修了这个」**——diff 校验、逐 chunk 比对，防止修复引入回归（本项目发生过两次「修 A 坏 B」）。
