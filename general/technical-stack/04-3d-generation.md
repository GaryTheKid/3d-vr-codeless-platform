# 04 · 3D Section Generation & Editing — the most worked-on subsystem

> Feature: each `vr` section gets its own interactive Three.js scene, generated by a
> tool-looping sub-agent, snapshotted per section, restorable across section switches,
> saves, exports, and GitHub Pages. **Read this doc before touching anything 3D.**
> Battle history behind every mechanism here: `/assets-recyclable/pain-log.md` (P17–P21)
> and `/assets-recyclable/golden-features.md` (§11–14).

## Architectural invariant

**There is exactly ONE live scene graph (`sceneRoot`).** Every VR section persists its
own ObjectLoader JSON into `section.vr.scene`; the live graph is a *view* of one
section at a time. VR fills are strictly serial (shared-viewport mutex). Any future
attempt to parallelize VR generation must first give each fill its own isolated
scene instance — do not parallelize on the shared `sceneRoot`.

## Fill lifecycle (one VR section)

```
beginVrSectionFill(id)
  save prior live section → fillingVrSectionId = id (HARD PIN)
  clearScene + ensureStudentRig
  section.vr.scene = null           ← never persist an empty "begin" snapshot
runVrToolLoop
  per tool_use:
    ensureVrFillSceneBound(id)      ← pin only; NEVER restores from disk mid-fill
    execTool(...)                   ← mutates sceneRoot
    restoreViewerAfterVrFillTool(id)← stampFillOwnership + save live (no camera)
post-fill ladder:
  empty (countTeachingObjects()===0) → CRITICAL RETRY loop → seedMinimalVrFallback
  unrestorable geometries → rebuild loop (SNAPSHOT-SAFE violation repair)
  duplicate of a peer (vrSceneSignature match) → distinct-rebuild loop
finishVrSectionFill(id)
  drop objects whose userData.vrSectionOwner ≠ id   ← isolation guarantee
  captureSceneGraph → section.vr.{scene,camera}
  unpin
```

### Fill sub-agent prompt (in `fillVrSection`)

Key blocks — keep all of them when editing:
- **AHA CONSTRUCTION** (highest priority): manipulable centerpiece from `buildIdea`.
- **DISTINCTNESS**: `[Peer 3D scenes]` object lists are forbidden to rebuild.
- **SNAPSHOT-SAFE GEOMETRY**: only core parametric geometries or hand-built
  BufferGeometry; **never** EdgesGeometry/WireframeGeometry/TextGeometry (they don't
  survive ObjectLoader). Wireframe → `material.wireframe = true`.
- **PANEL LAYOUT**: panels flank (x≈±7) or sit behind; ≤2 free panels; quiz panel high (y≈5).
- **LANGUAGE LOCK**: all student-visible 3D text in the UI language.
- **HARD**: ≥2 teaching objects + ≥1 panel; ~10 tool calls max.
- Excluded tools: outline structure mutators + all `course_*`.

### Dedup machinery

`vrSceneSignature` fingerprints **content**, not names: normalized builderCode
(comments/numbers stripped) + panelSpec text; needs ≥2 parts else returns `''`.
`seedMinimalVrFallback` hashes the section id into shape+color so even two fallback
scenes differ.

## Section switching (teacher clicks A → B → A)

`syncLiveVrSceneWithOutline` on `outline-changed`:

1. If `fillingVrSectionId` set → **hard pin**: toast + force active section back. No swap.
2. If play mode on → `stopPlayForSectionSwitch()` (play-reset restore must not paste A onto B).
3. `saveLiveSceneToSection(A)` — guarded: an empty live graph does NOT overwrite a
   non-empty snapshot unless `liveGraphClearedByCode` says the wipe was intentional.
4. `loadSectionScene(B)`: `restoreSceneGraph` + `restoreCameraState` (zoom forced to 1).

`restoreSceneGraph` resilience chain: full `ObjectLoader.parse` → on failure
`parseSceneChildren` per-child salvage → per-object `reviveObject` (re-run
`builderCode` / rebuild by `assetId`) → `ensurePanelVisuals` (panel repair) →
oid counter realignment. **One bad object never empties a section.**

## The userData contract (what persists)

| Key | Persists | Meaning |
|-----|----------|---------|
| `oid` | ✓ | Stable id `oN` — agents reference objects by it |
| `assetId` | ✓ | Prefab id → rebuild via registry |
| `builderCode` / `updateCode` / `clickCode` / `grabCode` / `dragCode` / `releaseCode` | ✓ (strings) | Recompiled on load (`reviveObject`); runtime function twins never persist |
| `panelSpec` | ✓ | JSON-safe panel mirror `{title,lines,accent,width,live}` |
| `panelData` | ✗ | Live canvas/texture — stripped before serialize; zombies deleted (`isUsablePanelData`) |
| `vrSectionOwner` | ✓ | Fill ownership stamp; foreign owners dropped at finish |
| `system` / `studentRig` / `editorOnly` | ✓ | Never cleared / hidden from students / stripped in export |
| `solid` | ✓ | Collision participation (`false` exempts subtree parts) |
| `anim` | ✓ | Declarative animation `{type,speed,…,selfSpin}` — never replace wholesale |
| `behaviorDesc` | ✓ | NL description = retrieval index for large scenes (must stay fresh) |
| `quiz` | ✓ | Quiz panel state (`quiz.done` gates unlock chains) |

## Snapshot slimming (`slimSnapshot`) — why saves fit in localStorage

- Top-level nodes with `builderCode` serialize as transform+userData husks (children
  dropped — the builder re-creates them).
- Meshes with `panelSpec` drop their `material` (canvas PNG data-URLs were the main
  quota killer); `rehydratePanel` redraws from spec on load.
- `pruneUnreferenced` removes orphaned geometries/materials/textures.
- Quota still exceeded → `writeProjects` evicts draft/oldest projects and retries.

## Known-fragile list (treat as regression tests when editing)

1. Outline events during fill — must stay `{silent:true}` for VR status updates.
2. Empty-scene saves — guards in `saveLiveSceneToSection` + `beginVrSectionFill(scene:null)`.
3. EdgesGeometry in `create_custom_object` code (prompt-banned; prefabs may use it
   because `assetId` rebuild bypasses geometry JSON).
4. `panelData` zombies after JSON round-trip — always go through `isUsablePanelData`.
5. Play-mode restore vs section switch ordering (`stopPlayForSectionSwitch`).
6. Camera `zoom` NaN/0 poisoning the shared orbit camera (sanitize on restore).
7. Live panels degrade to static after restore (spec.live kept, function gone) — by design.
