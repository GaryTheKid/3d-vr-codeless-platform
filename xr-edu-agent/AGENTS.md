# AGENTS.md — Project Guide for AI Agents

> This file is for AI coding agents that maintain or extend this project. Humans should read README.md first.
> **Product evolution** (pure 3D/VR → multimodal Outline + planned KG pipeline): see **[EVOLUTION.md](./EVOLUTION.md)**. Workflow visualization: `js/agent/agent-viewer.html` (**agent-map v5**).

## What This Project Is

XR EduAgent: a pure frontend (no build step) **multimodal lesson authoring** platform. Teachers command a built-in Agent with natural language to build a **Learning Outline** (Chapter → Section). Section types: **`vr`** (Three.js/WebXR scene), **`reading`**, **`h5`**, **`quiz`**. Stack: React 18 page shell (ESM CDN + HTM, no JSX build) + native ES Modules + Three.js 0.160 (importmap CDN) + AStone Claude China proxy (Messages API compatible; official Anthropic direct connection is forbidden).

Run: `python server.py` (from the **repository root**; static serve + `/__log` + `/__export` + `/__doc/convert` Docling); entry is root `index.html`. No npm dependencies, no bundling.

## Key Data Structures

**AssetSkill** (registry.js):
```js
{ id, name, icon, category,
  description,   // Natural language: what this is (shared by humans and LLM)
  prompt,        // Prompt component: when / how to use pedagogically (injected into LLM)
  tags: [],      // Search keywords
  code: { module, symbol },   // Code location (for future community distribution)
  size: { footprint: [w,h,d], tris },
  build: () => THREE.Object3D }
```

**Scene object conventions** (all in obj.userData):
- `oid` stable id (Agent references objects by it); `assetId` source asset; `displayName`/`icon`
- `anim` animation `{type: spin|orbit|swing|float|bounce|ramp, speed, radius?, cx?, cz?, amplitude?, base?, selfSpin?}`; moved to `savedAnim` when disabled. selfSpin: orbit includes spin by default — set false to turn off alone; other types set true to add spin — the inspector “self-spin” checkbox only toggles this field and **must never replace anim wholesale** (non-destructive principle: a single UI control only changes its own logic)
- `expAction` student-clickable lab actions (tube/lamp/duct/bottle/splint/npc); moved to `savedExpAction` when disabled
- `customUpdate(dt,t,obj)` AI-written per-frame behavior (run by loop.js; auto-disables after ~1s of continuous errors); `customClick(obj)` AI-written click interaction (= legacy alias of activate; dispatched by interaction.js; priority below expAction, above select); moved to `savedCustomUpdate/savedCustomClick` when disabled
- Semantic interaction events (device-agnostic; dispatched by interaction.js; PC/XR Interactors map automatically): `onActivate(obj,detail)` (click/trigger), `onGrab/onDrag/onRelease(obj,detail)` (PC hold-drag / XR grip); detail.point is world coordinates
- `custom` marks code-generated objects; `behaviorDesc` teacher-facing behavior description (NL Inspector); `builderCode/updateCode/clickCode/grabCode/dragCode/releaseCode` source strings (enter context after 📌 pin for model self-audit/rewrite)
- `compDesc` custom component description written by the teacher in NL Inspector
- `panelData` panel canvas data (includes live functions; not serializable); `panelSpec` its JSON-safe mirror (rides with scene serialization; rehydrated on load); `isBillboard` panel faces camera

## How to Do Common Extension Tasks

- **Add a new asset**: write a builder in builders.js → register an AssetSkill in registry.js (write description/prompt carefully — the LLM selects by them). Library UI and add_asset pick it up automatically
- **Add a new scene template**: add a SCENARIOS entry in scenarios.js (match regex must not collide; clearScene first inside run). Offline keywords and build_template pick it up automatically
- **Add a new Agent tool**: append `{name,label(L() bilingual),description,input_schema,exec}` to the appropriate array under js/agent/tools/. No need to edit index.js or orchestrator; do sync the agent-map.js tool catalog (see js/agent/README.md)
- **Add a new Agent skill**: create a same-named module under js/agent/skills/ (registry style: globalThis.XR_AGENT_SKILLS push; zero deps; no import/export; fields include Chinese name/description/prompt + English nameEn/descriptionEn/promptEn — missing English falls back to Chinese in the EN viewer) → import in index.js → add filename to manifest.js; Planner can select it automatically; skills viewer syncs automatically
- **Add a new proxy model endpoint**: add an endpoint mapping in llm.js MODELS; do not restore frontend calls to api.anthropic.com
- **Add a new virtual object / component card**: push in hierarchy.js getVirtualObjects(); component `{id,icon,title,desc,toggled?,onToggle?,onEdit?}` (onEdit returning true means apply was handled)

## Caveats / Pitfalls

- No cyclic imports of business functions across modules; cross-module notifications always go through events.js (e.g. labs speaking in chat → emit('agent-say', html))
- Scene objects may only hang as direct children of sceneRoot (hierarchy / ray-select assume this); effect layers (chemLab.fx) hang on scene and stay out of hierarchy
- clearScene fires onSceneClear hooks; new labs must register hooks to clear their own state and effects
- Panel text is Canvas-drawn; after content changes you must drawPanel(pd) or use a live function
- attachLabel inverse-scales by parent scale — scale first, then attachLabel
- Watch single-character false positives in Chinese regex (historical bug: the character 「摆」 sent a geometry lesson into the pendulum scene)
- Model thinking (adaptive thinking): Fable 5 / Mythos 5 always on, and **thinking tokens count toward max_tokens** — too-small max_tokens get eaten by thinking → “no text / no tool calls” or truncated JSON (historical bug: Fable reported “Planner returned no JSON” / only “Done.”). Mitigations: generous max_tokens (planner ≥3072, executor ≥8192); planner uses effort:'low'; never send thinking:{type:'enabled'|'disabled'} to these models (400); depth only via output_config.effort. On stream round-trip, thinking blocks must return signature unchanged
- Planner JSON parsing uses extractJSON (strip fences → direct parse → brace-matching scan); parse failure does not hard-crash — falls back to a complex plan
- api-keys.txt is in .gitignore; never put secrets in any committed file
- No build after edits — refresh the browser; must be served over http (ES modules). For AI-behavior debugging, prefer `python server.py` and inspect logs/*.jsonl (llm_call events include usage and stop_reason; for “Done.” / empty output, check max_tokens truncation first)
- In AI-generated customUpdate, conditional T.say/T.toast must latch (edge-trigger once); sandbox has a 5s same-text throttle fallback, but the real fix is prompting (experiment-logic skill)
- Interactions always go through semantic events (interaction.js) — do not bind mouse/controllers in object code; interactions dispatch only in **play mode** (playMode, ▶ button) — in edit mode every click selects; hierarchy component ▶ preview is mode-independent; entering an XR session auto-switches to play; AI can toggle via set_environment {play_mode}
- Hover glow / click flash are platform feedback (highlight.js); AI/content code must not reinvent hover; “result feedback” (geometry/panel changes, toast after interaction) stays with content code
- In-room UI panel show/hide is a platform rule (room-ui-visibility.js: viewer outside room → hide that room’s panels; inside → top-layer panels): user-requested behavior — do not remove unless the user explicitly asks; content code must not invent panel occlusion logic
- Entities that block student walking (walls/fences) mark `userData.solid = true` (ancestor marks apply to subtree; `solid = false` can exempt parts like stair rails); blocking is relative to player foot height — solids with top face ≤ foot+0.45m are “steppable ledges” (groundHeightAt sampling; stairs/second floors become walkable); taller ones are walls; works in editor and export player; runtime solid changes use T.setSolid (rebuilds collision boxes)
- Large scenes (object count > context.js FULL_JSON_MAX) auto-switch context to “summary index + prefetch”: behaviorDesc is the retrieval index — any behavior-mutating tool call must sync-update description, or later turns retrieve the wrong object; new scene-mutating tools should call markTouched(obj) in exec
- Prompt caching needs a stable prefix: BASE_SYSTEM / tool defs / asset catalog are the cache prefix — changing them invalidates all caches (functionality unaffected; just pays cache-write that turn); variable system content (skill prompts, etc.) may only append after the stable block
- Object granularity: one object = one logical entity; system-scale scenes split into many objects + a controller holding shared state (scene-organization / experiment-logic skills have good/bad examples)
- **All user-visible copy must be bilingual**: static DOM uses data-i18n (+ add keys to i18n.js DICT); JS UI chrome uses t(); content copy (templates/labs/descriptions/toast) uses L(zh,en). L/t may evaluate at module load (language switch = full-page reload). **Agent language lock**: orchestrator system prompts (`baseSystem` / planner / executor / ask) are fully EN or fully ZH from `isEN()`; `skillCatalogForLLM` / `skillPrompts` inject `descriptionEn`/`promptEn` in EN mode. UI English → final chat summary, plan steps, panel text, and `report_progress` titles must be English; UI Chinese → all Chinese
- Anything in userData that is a function / THREE object / canvas is non-serializable: stripUserData peels them before save/export; state that must ride with the scene needs a separate JSON-safe mirror (see panelData→panelSpec pattern)
